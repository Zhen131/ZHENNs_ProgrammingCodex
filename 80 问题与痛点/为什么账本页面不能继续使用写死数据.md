# 为什么账本页面不能继续使用写死数据

## 痛点

写死的 `summaryRows` 和 `trades` 可以让页面看起来像账本，但它们本质上只是样板图。用户新增交易后，页面里的假交易列表和假资产汇总不会自然变成真实数据。

如果页面继续依赖写死数组，就会出现：

- 保存交易按钮没有真的把表单数据写进账本。
- 交易列表不会随着新增交易变化。
- 资产汇总不是从交易和价格计算出来的。
- 假数据容易被误认为真实数据。

## 以前怎么解决

早期开发常用写死数据搭页面骨架，这有价值：可以先确认 UI 结构和视觉布局。但当目标变成打通业务链路时，写死数据就会挡住真实问题。

账本系统真正要验证的是：

```text
页面表单
-> TradeDraft
-> validateTradeDraft
-> Trade
-> LedgerData.trades
-> calculatePositions
-> Position[]
-> 页面展示
```

## 技术演进

更合理的方向是让页面从 [[React State（React 状态）]] 读取统一账本：

- 交易列表读取 `ledgerData.trades`。
- 资产汇总根据 `Trade[]` 和 `PriceSnapshot[]` 计算。
- `Position[]` 作为 [[Derived Data（派生数据）]] 展示，而不是手动保存成第二套事实。

在 Week 4 阶段，[[LedgerData（账本数据对象）]] 可以先放在 React 内存里。刷新后丢失是当前阶段接受的限制；后续再接入 IndexedDB 或其他持久化方案。

## 我的理解

写死数据适合搭样子，不适合验证账本系统是否真的工作。页面应该从同一份账本状态读取数据，让新增交易、交易列表、资产汇总和持仓结果沿着同一条数据链路变化。
