# 为什么 AI Agent 比普通聊天消耗更多 Token

## 痛点

你对 Agent 说了一句"修一下这个 bug"，十个字。账单回来，几十万 token。

你会觉得被坑了。其实不是：你打的那十个字，只是整个任务里进入模型的东西的零头。

## 怎么解决的

先看清楚一次 Agent 任务到底发生了什么：

```text
读仓库规则和任务描述
  ↓
搜代码、读文件
  ↓
分析、决定调哪个工具
  ↓
跑测试、读报错日志
  ↓
改代码、再验证、再分析
```

每一个箭头都是一次模型调用。每次调用都有新的输入和输出 [[Token（语言处理单位）]]。更要命的是，为了让模型记得自己做到哪了，前面几轮的对话、读过的文件、工具的返回，很多都要再塞一遍进 [[Context Window（上下文窗口）]]。所以用量不是加法，是接近乘法。

把账单放大的几个东西：

- 仓库大、日志长，Agent 又没定向搜，整个目录读进去。
- 工具返回一大坨，后面每轮都带着它。
- 一次没改对，测试挂了，再来一轮，再来一轮。
- 模型输出很长的分析和补丁。
- 推理模型在回答前还要"想"，reasoning token 也计费。
- 开了多个 Agent 并行，每个都有自己的一套上下文。

Prompt Caching（提示缓存）能救一部分：如果每轮都带着同一份长前缀，API 可以不重算，按低价收。但它只是让重复的部分便宜，新读的文件、新改的代码、新的输出，一个都省不了。

**怎么少花：**

- 看整个任务的累计用量，别只看你打了几个字。
- 账单拆开看：input、cached input、output、reasoning 分别多少。
- 让 Agent 定向搜、分段读，别让它一次吞掉整个仓库。
- 工具输出太长就截断，长任务里把已经确认的信息压缩掉。
- 开始之前把问题和验收标准说清楚，少返工就是少花钱。

但别为了省而省。该读的代码、该看的测试日志，不读它就会改错，改错比多花 token 更贵。目标是砍掉无关的上下文和重复的调用，不是砍掉必要的。

## 我的理解

Agent 的计费单位不是"我说了几句话"，是"整个循环里模型吃进去和吐出来的所有东西"。一句短指令，背后是一长串工具调用，每一步都在往窗口里加东西。
