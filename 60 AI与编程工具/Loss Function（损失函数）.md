# Loss Function（损失函数）

## 一句话

Loss Function 把"模型这次预测得有多差"压成一个数。训练的全部目标就是让这个数变小——模型学什么、往哪个方向学，都由它定义。

## 背景：它出现前的问题

要让机器自动"学"，必须先回答：什么叫学得好？

人判断对错很容易，但"这张图分类错了"不是机器能自动改进的信号。机器需要一个**可计算、可比较、最好还可求导**的数，才能知道参数往哪边调会更好。没有这个数，就没有自动优化，只剩人手调规则。

## 它解决了什么

把模糊的"好 / 坏"变成一个数值目标，训练从此变成一个数学优化问题：找到让 loss 最小的参数。后续的 [[Gradient Descent（梯度下降）]] 只负责"怎么走到最低点"，而 Loss Function 负责"哪里算低"。

## 核心机制

- 模型给出预测 `ŷ`，和真实标签 `y` 比较，得到单个样本的损失 `L(ŷ, y)`。
- 整个数据集上取平均，就是训练要最小化的 Objective Function（目标函数）。
- 常见形式：
  - **MSE（均方误差）**：回归任务，`(ŷ - y)²`，预测值离得越远罚得越重。
  - **Cross-Entropy（交叉熵）**：分类任务，衡量预测的概率分布和真实分布差多远。
- 可以往里面加 Regularization（正则化）项，比如参数的平方和。意思是把"别把模型搞得太复杂"也写进目标里——这是提升 [[Generalization（泛化）]] 的常用手段。
- 多目标任务（既要准、又要快、又要公平）通常写成加权和：`L = w₁L₁ + w₂L₂ + ...`。**权重怎么定，数学不替你决定**，那是人的判断。

## 最危险的不是训练慢，而是优化错了目标

Loss Function 定义错了，优化越强，结果越荒谬。几个真实的例子：

- **不平衡数据用 Accuracy（准确率）当目标**：99% 样本是负例，模型全猜"负"就能拿 99%，看起来很好，实际什么都没学。
- **Reward Hacking（奖励黑客）**：[[Reinforcement Learning（强化学习）]] 里 reward 就是 loss 的对应物。Agent 会找到让分数飙高、但完全不是你想要的行为——比如赛艇游戏里绕圈刷道具不冲终点。
- **Goodhart's Law（古德哈特定律）**：一个指标一旦变成优化目标，它就不再是好指标。代理指标 proxy 和真实目标之间的缝隙，会被优化器放大。

所以在调模型之前，先问一句：这个 loss 真的代表我要的东西吗？

## 局限性

- 只能表达你写得出来的东西。"好看""有用""合理"这类目标很难写成公式，只能找代理指标。
- 要配合 Gradient Descent 使用的话，必须可微（或至少能估计梯度）。
- 训练 loss 低不等于模型有用，见 [[Generalization（泛化）]]。

## 关联

- [[Gradient Descent（梯度下降）]]：最小化 Loss Function 的标准算法；Loss 定义"哪里低"，GD 负责"怎么走"。
- [[Supervised Learning（监督学习）]]：Loss 衡量预测 `ŷ` 和标签 `y` 的差距，是监督学习训练的核心信号。
- [[Reinforcement Learning（强化学习）]]：reward 是 RL 里的"反向 loss"，同样面临定义错目标的风险。
- [[Generalization（泛化）]]：正则化项写进 loss，是防止过拟合的手段之一。
- [[Life as Gradient Descent（把人生当作梯度下降）]]：把"优化错了目标函数"迁移到人生选择上的思维模型。
