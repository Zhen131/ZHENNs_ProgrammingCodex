# Context Window（上下文窗口）

## 一句话

Context Window（上下文窗口）是模型在一次调用中能够纳入计算的有限 token 范围，通常需要在输入、历史信息、工具结果、推理用量和输出空间之间分配。

## 背景：模型没有无限工作台

长对话、整仓库代码和大量日志不能无限塞进一次调用。内容经过 [[Tokenization（分词）]] 后会占据窗口；超过模型或接口限制时，请求可能失败，也可能由产品截断、压缩或摘要旧内容。

## 核心机制

可以把上下文窗口理解为模型当前回合的有限工作台：

```text
系统指令 + 对话历史 + 当前请求 + 文件/工具结果 + 输出预算
                         ≤ Context Window
```

具体计数口径依模型与 API 而异。有些推理模型还需要为内部 reasoning token（推理 token）保留空间，因此不能只看用户可见文字长度。

## 对 Agent 的影响

AI Agent 会反复读取文件和工具结果。为了让后续步骤继续掌握任务状态，系统可能重新发送、缓存、裁剪或总结上下文。这既影响 [[Token（语言处理单位）]] 用量，也影响模型能否保留关键细节。

## 局限性

- 窗口更大不等于模型对所有内容都能同样准确地利用。
- 上下文容量不等于长期记忆；跨调用是否保留信息取决于应用怎样管理状态。
- 把无关文件全部放进上下文会增加成本和噪声，不一定提高质量。
