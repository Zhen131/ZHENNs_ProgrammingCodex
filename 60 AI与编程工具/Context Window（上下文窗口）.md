# Context Window（上下文窗口）

## 一句话

Context Window 是模型一次能"看到"的最大范围，按 [[Token（语言处理单位）]] 计。你给它的东西加上它要吐出来的东西，总共不能超过这个数。

## 背景：模型没有无限的工作台

你可能想把整个仓库、三天的聊天记录、一万行日志一股脑塞给模型。塞不下。模型每次调用只有一张固定大小的桌子，桌子上放不下的，要么请求直接报错，要么产品偷偷帮你把旧的内容截掉或压缩掉——而你往往不知道它截了什么。

## 核心机制

桌子上放的东西，全部要算进窗口：

```text
system prompt + 对话历史 + 你这次说的话 + 文件/工具返回的结果 + 留给输出的空间
                                  ≤ Context Window
```

两个容易漏算的地方：

- **输出也占窗口。** 窗口 200k，你塞了 195k 进去，模型就只剩 5k 的空间回答你。
- **推理模型的思考也占窗口。** 它在回答前"想"的那部分 reasoning token 要留位置，所以你看到的文字长度不等于实际占用。

不同模型、不同 API 的计数口径不完全一样，具体数字以文档为准。

## 对 Agent 的影响

Agent 会反复读文件、跑命令、看结果。每一轮的结果都要留在桌子上，下一轮才知道自己做到哪了。所以桌子很快就满。系统只能做三件事之一：重新发一遍（贵）、缓存（便宜但有条件）、裁剪或总结旧内容（便宜但可能丢细节）。

这就是为什么长任务跑到后面，Agent 会"忘记"开头说过的话——不是它记性差，是桌子上的东西被收走了。

## 局限性

- 窗口大不等于模型对窗口里每一处都同样上心。塞进去 50 万 token，中间那部分很可能被忽略。
- 窗口不是记忆。这次调用结束，桌子就清空了。下次还记得什么，看应用层怎么存。
- 把无关的文件全塞进去，不但花钱，还会让模型分心。少而准比多而全好。
