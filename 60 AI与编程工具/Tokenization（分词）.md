# Tokenization（分词）

## 一句话

Tokenization（分词）是 tokenizer（分词器）把文本或代码转换成 [[Token（语言处理单位）]] 序列，并把 token 映射为模型可处理 ID 的过程。

## 背景：模型为什么不直接读取字符串

神经网络需要数值输入，而自然语言中的词汇数量巨大、不断变化，还包含生词、标点、代码和多种语言。若只按完整单词建立词表，词表会过大且无法覆盖新词；若只按字符切分，序列又可能过长。

现代 LLM 通常使用 subword（子词）或 byte-based（基于字节）等切分方案，在词表规模、未知词处理和序列长度之间折中。

## 核心机制

```text
原始字符串
  ↓ tokenizer 按自身词表与规则切分
token 序列
  ↓ 映射
token ID 序列
  ↓ embedding 等模型计算
模型内部表示
```

切分结果依赖具体 tokenizer。相同文本交给不同模型，token 数可能不同；空格、标点、大小写、中文、emoji 和代码符号也都会影响结果。

## 它解决了什么

- 把任意文本转为有限词表中的数值 ID。
- 让常见片段可以合并，减少序列长度。
- 让生词或罕见字符串仍能被拆分处理，而不必全部列入词表。

## 局限性

- token 边界不等于人类理解的词义边界。
- 不同语言的 token 效率可能不同，不能用统一“字数换算率”精确估算。
- Tokenization 只是输入表示步骤，不代表模型已经理解文本。

## 关联

- [[Token（语言处理单位）]]：Tokenization 的直接产物。
- [[Context Window（上下文窗口）]]：切分后的 token 数决定文本占用多少上下文。
- [[为什么 Token 不能直接等同于 MB]]：同样的字节大小经过不同 tokenizer 后可能产生不同 token 数。
