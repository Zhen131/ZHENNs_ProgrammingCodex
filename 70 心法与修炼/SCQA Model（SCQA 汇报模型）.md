# SCQA Model（SCQA 汇报模型）

## 一句话

SCQA Model 是一种面向讨论和决策的长版本汇报结构，按 Situation（背景）→ Conflict（冲突）→ Question（问题）→ Answer（建议）四步组织内容，用于让不熟悉情况的人在同一个问题上形成共识并做出选择。

## 背景：不是所有汇报都能结论先行

[[PREP Model（PREP 汇报模型）]] 的前提是"对方熟、我有方案"。现实里经常两条都不成立：

- 一对多的评审会上，有同事完全没接触过这个项目。
- 我在向导师汇报一个他没有接触过的方向。
- 我遇到了一个自己解不掉的卡点，需要大家一起想。

这些场合直接抛结论会失效：听众还不知道问题是什么，就没有接住结论的地方。SCQA 的作用是先把所有人拉到同一个问题上，再谈答案。

## 适用条件

满足任一条即可用 SCQA：

1. **有人不熟悉当前情况。** 一对多汇报、跨方向汇报、向新加入的人交代。
2. **我没有预案。** 遇到困难不知道怎么解，需要头脑风暴或上级拍板。

## 核心机制：四步结构

```text
S  Situation  背景    我们原本在做什么（就近背景）
C  Conflict   冲突    但是撞上了什么矛盾
Q  Question   问题    所以问题是什么，该怎么办
A  Answer     建议    我的倾向是哪个，为什么
```

### 1. Situation：只讲就近背景

这是 SCQA 最容易崩的一步。

背景必须**又近又短**。它唯一的目的是让听众理解下一步的 Conflict，不是把领域科普一遍。

一个反面例子：要讨论"AI 对程序员岗位的冲击"，结果第一页 PPT 从机器学习原理、模型训练方式讲起。等讲到真正的矛盾时，时间已经烧掉一半，全场注意力也散了。

判断标准很简单：**这句背景如果删掉，听众还能不能听懂后面的冲突？** 能，就删。

### 2. Conflict：冲突是背景的目的地

Conflict 是整个 SCQA 的重心：我们原来的做法撞上了什么障碍、什么矛盾、什么做不下去的地方。

讲 Conflict 时就要开始往"选择"的方向收。不要停留在"很难"这种模糊描述上，而要落到具体的对立面：要么 A 要么 B，两边各有代价。

### 3. Question：尽量出选择题，不要出问答题

这是 SCQA 里最影响对方体验的一步，也是区分汇报水平的地方。

```text
选择题（好）：方案 A / 方案 B，各自的收益和代价是 ...，您倾向哪个
问答题（差）：我不知道怎么办，您帮我想想
```

区别在于**占用对方哪种资源**：

- 选择题占用的是**判断力**。对方在你已经铺好的选项上做决策，几十秒就能给出方向。
- 问答题占用的是**脑力和信息重建成本**。对方要从零开始理解问题、搜索方案、评估可行性，这部分工作本来应该由掌握细节的你来做。

出选择题的要点：

- 选项控制在两到三个，A/B/C/D/E 全列出来等于没做筛选。
- 每个选项都要写清收益和代价，而不是只写名字。比如技术选型选 Java 还是 Python，要写各自在团队熟悉度、生态、上线速度、长期维护上的具体差异。
- 结构长这样：`选 A：好处是…，代价是…；选 B：好处是…，代价是…`

选择题还有一个附带好处：如果对方能力足够，他会看穿 A 和 B 都不值得选，然后补上一个 C。这时候你不仅拿到了更好的方案，对方也确实展示了他的判断力——**这是自然发生的向上管理，不是刻意安排的表演**。

问答题不是禁止，而是保留给真正超出自己能力边界的难题。频繁出问答题，等于把自己的工作外包给上级。

### 4. Answer：给出自己的倾向

最后明确表态：我倾向 A，理由是什么；或者我倾向 B，理由是什么。

有倾向和没倾向的差别很大。给了倾向，对方只需要确认或否决；不给倾向，等于把 Question 又抛回去一次，前面三步的铺垫就白做了。

倾向不等于最终决定。拍板权在对方，但**方案权在你**。

## 常见失败模式

- **Situation 过长。** 最典型的死法，背景讲完时间没了。
- **Conflict 不够尖锐。** 只说"有点困难"，没有把对立面摆出来，后面的 Question 就无从谈起。
- **Question 出成了开放题。** 明明手上有两个方案，却讲成"大家看看怎么办"。
- **选项没有代价。** 只讲每个方案的好处，对方无法比较，只能凭感觉选。
- **Answer 缺席。** 讲完问题就收尾，等着别人给答案。

## 局限性

- 比 PREP 长，不适合日常进度同步这类高频短汇报。
- 对方已经非常熟悉情况时，Situation 和 Conflict 会显得啰嗦，应该直接切 PREP。
- 选择题本身会框住讨论范围。如果 A 和 B 都建立在错误前提上，结构越完整，越容易把所有人一起带偏。所以选项之外要留一句"或者我这个框架本身有问题"。
