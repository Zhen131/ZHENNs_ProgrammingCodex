# PREP Model（PREP 汇报模型）

## 一句话

PREP Model 是一种结论先行的短版本汇报结构，按 Point（结论）→ Reason（理由）→ Example（例证）→ Point（收口）四步组织内容，用于向已经熟悉这件事的人快速同步判断。

## 背景：人天生按时间顺序讲事情

不训练的情况下，绝大多数人汇报会按自己经历的顺序讲：先说我做了什么，再说我遇到了什么，最后说所以结论是什么。

问题在于，听众在听到最后一句之前，**不知道该把前面的信息往哪儿放**。他必须一边听一边猜你要去哪里，猜错了就要回头重建理解。在 1:1 的时间交换比下，这部分损耗全部由听众承担。

PREP 的作用就是把结论从末尾挪到开头，让后面每一句都有明确的归属。

## 适用条件

两个条件同时成立时用 PREP：

1. **听众熟悉这件事。** 他和你在同一个领域，走过你正在走的路，不需要背景铺垫。
2. **我已经有方案或预案。** 这次汇报是来同步结论、取得确认的，不是来求助的。

典型场合：和导师的一对一进度汇报、邮件汇报、站会同步、把一个已经想清楚的技术决定告诉团队。

如果任一条件不成立，改用 [[SCQA Model（SCQA 汇报模型）]]。

## 核心机制：四步结构

```text
P  Point    结论      我的判断是 X
R  Reason   理由      因为 1、2、3
E  Example  例证      具体数据 / 案例 / 现场证据
P  Point    收口      所以 X，接下来我打算 Y
```

### 1. Point：先摆结论

第一句话就要让对方知道这次汇报指向什么目标、你的判断是什么。

它的作用是给听众一个"收纳框"。有了框，后面的理由和数据才知道往哪儿放；没有框，同样的信息只是一堆散落的事实。

### 2. Reason：点明原因

为什么是这个结论？发生了什么？理由一、理由二、理由三。

理由要编号、要并列、要收敛在三条以内。三条以上通常说明你还没想清楚主因，只是在罗列。

### 3. Example：用例子和数据支撑

到这一步之前，讲的全是你的主观判断。Example 负责把它变成可验证的东西：跑出来的数字、复现步骤、一段日志、一个对照实验。

**没有 Example 的 PREP 就是空的**。Reason 只说明了逻辑，Example 才说明了逻辑成立。

### 4. Point：再次收口

回到结论，并且比开头多说一句：接下来的动作是什么，需要对方做什么。

这一步不是简单重复。开头的 Point 是"我要讲什么"，结尾的 Point 是"所以我们要做什么"。

## 常见失败模式

- **P 被讲成了背景。** 开头讲了三十秒还没出现判断，实际上已经退化成流水账。
- **R 和 E 混在一起。** 边说理由边举例子，听众分不清哪些是推理、哪些是证据。
- **E 缺席。** 三条理由全是"我觉得"，一个数字都没有。
- **结尾不收口。** 讲完例子就停了，对方不知道你要他干什么，只好回一句"嗯，好"。
- **强行套用。** 对方明显不熟悉背景，还硬上 PREP，结论一出口对方就懵了。

## 局限性

- 不适合听众不了解背景的场合，结论先行会变成结论悬空。
- 不适合自己没有方案的场合。PREP 的结构里没有"我不知道怎么办"的位置。
- 结论先行会让汇报显得笃定，如果判断本身不牢靠，这种笃定会放大误导。不确定时要在 Point 里就标出置信度。
