# Derived Data（派生数据）

## 一句话

`Derived Data（派生数据）` 是依赖其他事实数据计算出来的数据；它不能脱离依赖的数据独立成为事实。

## 背景：它出现前的问题

复杂业务系统里，很多页面显示值看起来像数据，但其实是结果。比如当前持仓、平均成本、库存余量、购物车总价和统计汇总，通常都要根据更底层的事实记录计算出来。

如果系统同时保存事实数据和结果数据，就可能出现两套数据互相打架。

## 它解决了什么

Derived Data 这个概念帮助区分：

- 事实数据：用户真实录入或系统真实接收的记录。
- 派生数据：根据事实数据计算出来的结果，必须依附事实数据存在。

例如：

```text
订单明细 + 优惠规则
-> 购物车总价

交易记录 + 价格数据
-> 当前持仓和盈亏

入库记录 + 出库记录
-> 当前库存
```

前一组数据更接近事实来源，后一组数据是计算结果。

## 核心机制

核心原则是：

```text
事实数据要保存。
派生数据要计算。
```

比如用户什么时候买入、买入多少、成交价格是多少、手续费是多少，这些组成交易事实。当前持仓、平均成本和盈亏应该由这些事实计算出来。

如果同时长期保存 `Trade[]` 和手写的 `Position[]`，未来就可能出现：

```text
交易记录显示我有 0.01 BTC
持仓记录却显示我有 0.02 BTC
```

在 React 业务页面里，如果事实数据由 [[useReducer（React Reducer Hook）]] 管理，reducer 可以成为统一重算派生数据的地方：每次 `ADD_TRADE`、`DELETE_TRADE` 或 `UPDATE_TRADE` 后，都按同一套规则更新或重新计算结果，避免不同组件各算各的。

## 典型使用场景

- 从订单计算库存。
- 从交易记录计算持仓。
- 从明细账计算汇总金额。
- 从表单输入计算预览结果。
- 在复杂 React state 更新后统一重算持仓、汇总或校验结果。

## 局限性

派生数据不是永远不能缓存。性能压力大时，可以缓存计算结果；但缓存必须有清晰的失效和重算规则，不能让缓存结果变成和事实数据平行的第二套真相。

## 和其他概念的关系

- [[React State（React 状态）]] 可以保存事实数据，也可以短暂保存某些 UI 派生状态，但要小心一致性。
- [[useReducer（React Reducer Hook）]] 可以把事实数据修改和派生数据重算集中到同一套状态规则中。
- [[Reducer（状态归约函数）]] 是承载统一重算规则的一种方式。
- [[为什么派生数据不应该当成事实数据保存]] 是理解派生数据边界的问题入口。

## 进一步理解

- [[Instant（瞬间）]]：一条事件记录里，绝对时刻是事实，「哪一天」「星期几」「本月合计」都是从它加上地点算出来的派生数据。把日期当字符串截取保存，就是把派生结果当成了事实。
- [[UTC Offset（UTC 偏移量）]]：偏移量由「地点 + 时刻」算出，是结果；[[IANA Time Zone Database（IANA 时区数据库）]] 的时区名才是依据。存结果会丢掉依据，这是派生数据规则在时间建模上的具体表现。
