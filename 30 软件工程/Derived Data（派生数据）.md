# Derived Data（派生数据）

## 一句话

`Derived Data（派生数据）` 是依赖其他事实数据计算出来的数据；它不能脱离依赖的数据独立成为事实。

## 背景：它出现前的问题

复杂业务系统里，很多页面显示值看起来像数据，但其实是结果。比如当前持仓、平均成本、库存余量、购物车总价和统计汇总，通常都要根据更底层的事实记录计算出来。

如果系统同时保存事实数据和结果数据，就可能出现两套数据互相打架。

## 它解决了什么

Derived Data 这个概念帮助区分：

- 事实数据：用户真实录入或系统真实接收的记录。
- 派生数据：根据事实数据计算出来的结果，必须依附事实数据存在。

例如：

```text
订单明细 + 优惠规则
-> 购物车总价

交易记录 + 价格数据
-> 当前持仓和盈亏

入库记录 + 出库记录
-> 当前库存
```

前一组数据更接近事实来源，后一组数据是计算结果。

## 核心机制

核心原则是：

```text
事实数据要保存。
派生数据要计算。
```

比如用户什么时候买入、买入多少、成交价格是多少、手续费是多少，这些组成交易事实。当前持仓、平均成本和盈亏应该由这些事实计算出来。

如果同时长期保存 `Trade[]` 和手写的 `Position[]`，未来就可能出现：

```text
交易记录显示我有 0.01 BTC
持仓记录却显示我有 0.02 BTC
```

## 典型使用场景

- 从订单计算库存。
- 从交易记录计算持仓。
- 从明细账计算汇总金额。
- 从表单输入计算预览结果。

## 局限性

派生数据不是永远不能缓存。性能压力大时，可以缓存计算结果；但缓存必须有清晰的失效和重算规则，不能让缓存结果变成和事实数据平行的第二套真相。
