# Derived Data（派生数据）

## 一句话

`Derived Data（派生数据）` 是可以从事实数据计算出来的数据；它通常不应该被当成第二套事实长期手动保存。

## 背景：它出现前的问题

复杂业务系统里，很多页面显示值看起来像数据，但其实是结果。账本项目里的当前持仓、平均成本、市值和未实现盈亏，都是根据交易记录和价格快照计算出来的。

如果系统同时保存事实数据和结果数据，就可能出现两套数据互相打架。

## 它解决了什么

Derived Data 这个概念帮助区分：

- 事实数据：用户真实录入或系统真实接收的记录。
- 派生数据：根据事实数据计算出来的结果。

在账本项目里：

```text
Trade[] + PriceSnapshot[]
-> calculatePositions(...)
-> Position[]
```

`Trade[]` 和 `PriceSnapshot[]` 更接近事实来源，`Position[]` 是计算结果。

## 核心机制

核心原则是：

```text
事实数据要保存。
派生数据要计算。
```

比如用户什么时候买入、买入多少、成交价格是多少、手续费是多少，这些组成交易事实。当前持仓、平均成本和盈亏应该由这些事实计算出来。

如果同时长期保存 `Trade[]` 和手写的 `Position[]`，未来就可能出现：

```text
交易记录显示我有 0.01 BTC
持仓记录却显示我有 0.02 BTC
```

## 典型使用场景

- 从订单计算库存。
- 从交易记录计算持仓。
- 从明细账计算汇总金额。
- 从表单输入计算预览结果。

## 局限性

派生数据不是永远不能缓存。性能压力大时，可以缓存计算结果；但缓存必须有清晰的失效和重算规则，不能让缓存结果变成和事实数据平行的第二套真相。
