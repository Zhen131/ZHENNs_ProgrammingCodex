# 写作规范

> 这份规范只管一件事：卡片正文怎么写。存什么、放哪、怎么命名，看 `入库指南.md`。

## 一、写给谁

写给半年后的 Zhenn。他已经把这个东西忘光了，打开卡片是为了在 30 秒内捡回来。

他不是审稿人，不会挑你的措辞有没有留退路。他只想知道这东西是什么、为什么存在、怎么用。你写的每一句话，都是在对这一个人解释，不是在对公众发表。

AI 写出文档腔，根子在于把读者想象成了一个会挑刺的审稿人，于是每句话都加保险。把读者换回来，问题就解决了一半。

## 二、目标：读起来像轻散文

好的卡片读起来是顺的。眼睛从上往下走，不用回头，不用停下来拆句子，读完就懂了。

这不是口语。不要"啊、呢、吧、嘛、对不对、这个那个"。这些是说话时的填充词，落在纸上是噪音。

要的是口语的结构：短句、先例子后定义、直接对人说话。不要的是口语的腔调。

对比一下。方向标那篇转录（`90 素材与临时笔记/方向标-梯度下降与人生-转录.md`）逻辑顺、好读，但它是口播稿，语气词很多。`70 心法与修炼/Life as Gradient Descent（把人生当作梯度下降）.md` 是把它写成卡片之后的样子：逻辑一样顺，语气词全部去掉。后者才是目标。

## 三、四条规则

### 1. 先给例子，再给定义

读者在遇到某个具体东西的时候才会来查。先把那个东西摆出来，再说它是什么。

不好：
> Context Window 是模型在一次调用中能够纳入计算的有限 token 范围。

好：
> 你可能想把整个仓库、三天的聊天记录、一万行日志一股脑塞给模型。塞不下。模型每次调用只有一张固定大小的桌子，这张桌子就是 Context Window。

### 2. 一句话一个意思

"因此、从而、以及、并、同时"把三个意思焊成一句，读者要在脑子里拆开才能懂。拆开写。

不好：
> 同一段文本既有字节大小，也有 token 数，但两者没有固定比例，文本编码、语言、标点、代码结构以及 Tokenization 规则都会改变比例；更换模型的 tokenizer 后，token 数也可能变化，而文件的字节数不一定变化。

好：
> 同一段文字，字节数是固定的，token 数不是。换个模型，token 数就变，文件大小一点没变。中文、英文、代码，切出来的数量都不一样。

### 3. 敢下判断

"不一定、取决于、可能、通常"是在给自己留退路。退路留多了，读者读完不知道到底是怎样。

写判断。有例外就把例外写出来，不要用模糊词把判断糊掉。真的不确定，写"待确认"，不要写"可能"。

不好：
> 是否展示、如何计入输出与如何计费取决于具体模型和平台，不能笼统地说"思考一定不消耗 token"。

好：
> 推理模型回答前要"想"，想的那部分也计费。有的平台给你看，有的不给看，但都要算钱。

### 4. 对人说话

写的时候心里有一个具体的读者。他遇到了什么、他可能误以为什么、他接下来要做什么。"你会看到"、"你可能以为"、"你要做的是"这类句子是最直接的写法，但不是硬性要求——`Gradient Descent（梯度下降）` 那张卡几乎没用"你"，照样是在对人讲。判断标准是读起来像不像有人在给你解释，不是数"你"出现了几次。

不好：
> App Router 让 Next.js 可以根据目录和文件名自动理解应用结构。

好：
> 你不用再写一张"哪个 URL 对应哪个组件"的路由表。把文件放到约定的位置，Next.js 看目录名就知道这是哪个路由。

## 四、禁止

**名词堆。** 一行一个名词的列表，是在凑模板，不是在解释。三个以上的名词，写成一句话。

不好：
> CSS 负责表达界面的视觉层：
> - 颜色。
> - 字体。
> - 边距。
> - 布局。

好：
> CSS 管网页"长什么样"：这个按钮是蓝的还是灰的、字多大、离左边多远、在手机上要不要换成一列。

**裸链接。** `## 关联` 里只贴 `[[链接]]` 不说关系，读者还是得点开才知道为什么相关。每条都写一句关系。

不好：
> - [[Tokenization（分词）]]

好：
> - [[Tokenization（分词）]]：字符串怎么变成 token 串，就是这一步决定的。

**空节。** 模板的某一节写不出内容，就删掉那一节。不要为了填满写一句"暂无"或者把别的节的内容改写一遍。

**语气词。** 啊、呢、吧、嘛、呀、对不对、对吧、这个那个。一个都不要。

**书面套话。** 该、本卡片、上述、旨在、承载、语境、沉淀、升格、粒度、层面、维度、予以、进行、较为、应当。看到就换成平常的说法。

## 五、允许

**速查列表。** Git 命令、npm 命令这种"查一下怎么用"的清单，用列表是对的。放在一个叫 `## 速查` 的小节里。讲原理的部分不能用这种列表。

**代码块和表格。** 该用就用。一段最小可跑的代码比三段文字管用。

**类比。** 乐高、桌子、缓存、小本本。一个好类比能顶半页解释。但一张卡最多一个类比，两个类比打架读者更糊涂。

## 六、写完自检

读一遍，问自己：

- 第一段是不是先摆了一个读者会遇到的场景？
- 有没有一句话超过 40 个字还没有句号？
- 有没有"不一定、取决于、可能"后面没跟具体情况的？
- 读起来像有人在给你解释，还是像在念百科？
- 有没有三个以上名词排成的列表？
- `## 关联` 每条有没有写关系？
- 有没有语气词？

`check.py` 会抓名词堆、语气词和裸链接，只报 WARN。它抓不住长句、模糊词和百科腔，那三条靠自己读。
