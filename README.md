# ZHENN's Programming Codex

> 中文名：编程宝典

这是我（Zhenn）的个人编程知识库：用 Obsidian 组织，用 Git 管版本。

它是我**编程能力的缓存**。中学时我记不住 sin 30°、cos 90° 这些值，就把它们抄在一个小本子上，考试时直接翻，省下现场推导的五分钟。这个仓库做的是同一件事：学会一个东西，存成一张卡；以后忘了，搜一下就能直接用，脑子腾出来去想新的问题。

## 为什么要做它

AI 写代码越来越容易，代码也越来越容易变成 black box（黑盒）：项目能跑，但我不知道为什么能跑，出了问题也不知道从哪下手。

这个仓库记的不是资料，是我真正理解一个技术的过程：它出现之前人们卡在哪、它解决了什么、它的核心机制是什么、它有什么局限、我是在哪个项目的哪个坑里学会它的。

## 写法：中文讲逻辑，英文定术语

母语是中文，用中文想逻辑最快；但课程、考试、文档、报错全是英文，所以术语必须保留英文。

术语第一次出现写 `English（中文）`，比如 `Tokenization（分词）`、`Virtual DOM（虚拟DOM）`，之后直接用英文。

## 两种卡片

- **技术卡**：一个稳定的概念一张卡。`Closure（闭包）`、`Gradient Descent（梯度下降）`、`SCQA Model（SCQA 汇报模型）`。
- **问题卡**：一个"为什么"一张卡，解释技术为什么要存在。`为什么 React 不能直接修改 state`、`为什么存时间要存时区名而不是 UTC 偏移量`。

技术卡按领域放，问题卡全放 `80`。卡片之间靠 `[[wikilink]]` 直接连，不靠目录或索引文件中转。

## 结构

```text
编程宝典/
├── CLAUDE.md            # AI 入库规则（AGENTS.md 指向它）
├── 学习历程.base         # Obsidian Bases 视图：按时间看我学过什么
├── 00 工具与指南/        # 入库指南、模板、检查脚本
├── 10 计算机基础/
├── 20 编程语言/
├── 30 软件工程/
├── 40 Web与网络/
├── 50 数据与存储/
├── 60 AI与编程工具/
├── 70 心法与修炼/        # 沟通、汇报、思维模型——非代码但可复用
├── 80 问题与痛点/        # 所有问题卡
└── 90 素材与临时笔记/    # 还没消化的原始材料
```

怎么往里存、怎么判断该不该存，见 `00 工具与指南/入库指南.md`；正文怎么写，见 `00 工具与指南/写作规范.md`。

## 关于 `status`

每张卡有个 `status`：`草稿` 是 AI 写的或我还没仔细读过的，`已校` 是我亲自读过认可的。只有 `已校` 的卡才算可靠缓存，而且只有我能改成 `已校`。

## 目标

这个仓库会一直长下去。我希望它最后不只是笔记，而是我的个人技术地图。
